  <name>Task 1: Dashboard API route + useWizardState hook</name>
  <files>src/app/api/dashboard/[id]/route.ts, src/hooks/useWizardState.ts</files>
  <action>
    1. **Create `src/app/api/dashboard/[id]/route.ts`:**
       - GET handler: extract `id` from params, call `getDashboard(id)` from db.ts, return JSON
       - Handle not-found errors with 404 response
       - This route is needed so the client-side wizard can load dashboard data

    2. **Create `src/hooks/useWizardState.ts`** ("use client"):
       - Export `useWizardState(dashboardId: string)` hook
       - State shape: `{ dashboard: DashboardWithData | null; currentStep: number; loading: boolean; saving: boolean; error: string | null }`
       - On mount: fetch `/api/dashboard/${dashboardId}` to load dashboard data, set loading=false
       - `goToStep(step: number, data?: Partial<DashboardWithData>)`: sets saving=true, calls save function based on current step data, then updates currentStep and pushes URL with `?step=N` using `useRouter`
       - Save logic dispatches to the correct Supabase functions:
         - Dashboard-level fields (client_names, email, agent_key, slug): `fetch PATCH /api/dashboard/${id}` (add PATCH to the API route)
         - Sell data fields: `fetch PUT /api/dashboard/${id}/sell-data` (create this route too)
         - Buy data fields: `fetch PUT /api/dashboard/${id}/buy-data` (create this route too)
       - OR simpler approach: use direct Supabase client calls from the browser client since RLS allows authenticated CRUD. Use `createClient` from `@/lib/supabase/client` and call Supabase directly. This avoids creating extra API routes for simple CRUD.
       - Disable "Next" button while `saving=true` to prevent race conditions
       - `updateDashboardData(updates: Partial<DashboardWithData>)`: merge updates into local state without navigating (for in-step field changes)
       - Read `?step=N` from URL search params to initialize currentStep
  </action>
